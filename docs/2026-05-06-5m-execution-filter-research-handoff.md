# 2026-05-06 5m 执行验证与过滤研究交接

## 1. 今日目标

今天主要围绕一个问题推进：

```text
原始 1h 研究 run 的结果很好，但稳定池进入模拟盘前必须确认：
同一套 1h 信号在 5m 执行路径下是否仍然可信，以及最大回撤能否通过入场前过滤降低。
```

因此本轮没有修改主策略入场逻辑，也没有调整杠杆、单笔风险、止损或止盈参数，而是补齐了：

- 5m execution verification 的展示和状态口径
- 稳定池中基于 5m execution run 的过滤实验入口
- 最大回撤段交易归因后的下一轮过滤研究方向

## 2. 今日完成

### 2.1 修正单次分析 run 选择理解

确认了“单次分析”页右上角选择 Run 时，应该展示当前选中 run 的真实参数和结果，而不能误把旧 run、第一条 run 或默认 run 当成当前结果。

本轮排查中明确区分了三类结果：

- 原始 1h 研究 run：总收益率约 `18153.40%`
- 5m execution verification run：总收益率约 `86643.69%`
- 参数实验 / 批次里的其他 run：参数可能不同，不能直接混为同一 run 结论

关键纠正：

```text
原始样本 run 与 5m execution run 不是同一个执行口径。
即使参数相同，1h OHLC 执行与 5m 路径执行也可能产生显著不同结果。
```

### 2.2 修正稳定池 5m 执行验证展示

稳定池现在能显示 execution verification 摘要字段，避免只看到 1h 原始研究 run 而看不到 5m 验证 run。

当前稳定池候选可见：

- 最新 5m execution verification run id
- IS / OOS 执行验证摘要
- 5m 验证入口
- 5m 研究入口

这使稳定池从“只保存研究候选”推进到“能基于候选继续做执行验证和归因研究”。

### 2.3 新增基于 5m execution run 的过滤实验能力

新增了稳定池入口：

```http
POST /api/stable-candidates/{candidate_id}/execution-filter-experiments
```

该入口的语义是：

```text
稳定池候选
  -> 选中最新 5m execution verification run
  -> 复用原 1h parent run 生成信号
  -> 注入 signal_filters
  -> 再映射到 5m 执行时间线
  -> 生成 execution_filter_experiment run
```

这和旧的“通用过滤实验”不同：

- 旧入口偏 1h 参数实验研究
- 新入口专门回答 5m execution 路径下过滤后表现如何
- 新 run 的 `run_type = execution_filter_experiment`
- 新结果进入参数实验批次明细
- 不覆盖稳定池最新 `execution_verification`
- 不污染普通参数池 readmodel

### 2.4 前端新增 `5m过滤`

稳定池过滤实验列现在有两个不同入口：

- `通用`：原有 1h 参数 / 研究候选过滤实验
- `5m过滤`：基于最新 5m execution verification run 发起执行过滤实验

`5m过滤` 的目标不是重新搜索策略参数，而是验证：

```text
在原 1h 策略参数不变的前提下，
过滤掉某些入场前状态后，
5m 执行结果是否改善。
```

对当前 5m execution run 的最大回撤段做了人工分析。

- 区间止损率：`100.00%`

当前最强归因候选：

## 4. 当前使用方式

1. 打开本地 UI：

```text
http://127.0.0.1:8501
```

2. 进入稳定池。

3. 找到已有 5m execution verification 的候选。

4. 点击 `5m过滤`。

5. 等待任务完成后进入参数实验批次明细。

6. 对比过滤前后：

- 总收益
- 最终权益
- 交易数
- 最大回撤
- IS / OOS 表现
- 平均亏损
- 止损交易占比
- 是否只是避开单次回撤而牺牲大量正常盈利交易

## 5. 下一步建议

### P0：先跑最小 5m 过滤实验

第一轮不要做大量组合搜索，只验证最清晰的 4 个假设：

1. 只过滤 `震荡程度 >= 0.8`
2. 过滤 `震荡程度 >= 0.8` + `20根局部位置 >= 0.8`
3. 过滤 `震荡程度 >= 0.8` + `连续顺向 1-2`
4. 过滤 `震荡程度 >= 0.8` + `20根局部位置 >= 0.8` + `连续顺向 1-2`

目标不是找到最高收益，而是判断最大回撤是否下降，且 OOS / 交易数 / 收益质量是否仍可接受。

### P0：把归因候选转成显式过滤配置

当前 `5m过滤` 已具备执行能力，但默认过滤集合还偏“早期失败代理特征”。

下一步应把这次归因表中的最强候选转成显式 `signal_filter_sets`：

- `range_chop_score_20 >= 0.8`
- `local_position_20 >= 0.8`
- `consecutive_direction_count in 1..2`

并在 UI 上区分：

- 默认代理过滤
- 回撤归因候选过滤
- 人工选择组合过滤

### P1：增加过滤实验结果对比视图

当前结果进入参数实验批次明细，但还需要更直接的对比视图：

- 源 5m execution run
- 每个过滤 run
- 收益变化
- 最大回撤变化
- 交易保留率
- OOS 变化
- 过滤命中交易数

这样才能避免只看单个过滤 run 的绝对收益，忽略过滤带来的机会成本。

### P1：跨候选验证

如果 `震荡程度 >= 0.8` 在当前 BTC 5m execution run 上有效，不能直接进入稳定规则。

至少还要验证：

- 同一候选的 OOS 段
- ETH 或其他标的
- 相近参数组
- 不同回撤段

只有跨样本仍能降低回撤且不过度伤害收益，才考虑进入稳定池建议。

## 6. 当前风险与边界

- 当前最大回撤归因样本只有 `7` 笔，过拟合风险高。
- `方向 = 空头` 覆盖回撤段较多，但非回撤亏损率也高，不适合单独过滤。
- `震荡程度 >= 0.8` 是最强候选，但仍必须通过 5m execution filter experiment 验证。
- 本轮没有改变主策略逻辑，因此不会直接改善现有稳定池候选结果。
- 新增的 5m 过滤实验是研究工具，不是上线规则。
