# 参考仓库使用规范

## 1. 目的

本仓库允许引入外部开源项目作为 **只读参考仓库**，用于辅助工程设计、接口命名、任务组织和分析对象建模。

参考仓库不是本项目的实现基础，不得直接决定本项目架构。

本规范的目标是：

- 明确参考仓库的作用边界
- 降低 Codex 在编码时被外部框架“带偏”的风险
- 明确许可证与复制边界
- 保证本项目始终以本地设计文档为最高优先级

## 2. 优先级规则

实现时按以下优先级执行：

1. 本仓库设计文档  
   当前主文档为 [crypto-backtest-workbench-v1-implementation-design.md](/Users/liangxu/code/lhfx01/docs/crypto-backtest-workbench-v1-implementation-design.md)
2. 本仓库后续补充的本地规则和任务说明
3. `references/` 下的参考仓库

若参考仓库与本仓库文档冲突，**一律以本仓库文档为准**。

## 4. 当前建议参考仓库

### 4.1 Freqtrade

建议重点参考：

- 工程目录组织
- 回测任务入口
- 配置组织方式
- 策略注册和策略类接口
- 参数优化流程边界

不建议参考：

- live / dry trading 完整生命周期
- Telegram / bot 控制逻辑
- 与本项目 v1 不一致的订单语义
- 与本项目边界无关的兼容层

### 4.2 vectorbt

建议重点参考：

- 批量实验思路
- portfolio / trade / drawdown 分析对象
- 高速批量运算与结果组织方式

不建议参考：

- 直接继承其整体框架
- 将其许可边界不清的实现直接复制到本项目
- 用它替代本项目自己的 `FeatureArtifact` / `RunManifest` 设计

## 5. 许可证与复制边界

参考仓库允许：

- 阅读源码
- 学习接口设计
- 学习模块边界
- 学习任务流组织

参考仓库不允许：

- 整段复制实现代码到本项目
- 将外部仓库直接改造成当前项目
- 在未确认许可证影响前复用大段核心代码

要求：

- 如需借鉴具体实现，只能做小粒度、必要且可解释的参考
- 借鉴前优先改写为适合本项目边界的本地实现
- 若未来项目存在商业化可能，必须再次审查参考仓库许可证

## 6. Codex 编码约束

当 Codex 在本仓库内编码时，必须遵守：

1. 参考仓库仅用于学习工程组织、命名和接口思想
2. 不得直接复制整个框架结构
3. 不得将参考仓库里的 live trading / bot / stop loss / limit order 语义带入 v1
4. 不得因为参考仓库存在某对象就削弱本项目既有对象模型
5. 本项目已有对象优先级高于参考仓库中的类似对象

当前本项目高优先级对象包括但不限于：

- `DatasetSnapshot`
- `FeatureArtifact`
- `RunManifest`
- `ValidationSplit`
- `MetricPolicy`
- `StructuredWarning`
- `signal_on_bar_close_fill_on_next_bar_open`

同时必须遵守跨层依赖约束：

- `engine/strategy` 不直接依赖 `storage`
- `engine/execution` 不直接依赖 `app`
- `app` 不直接依赖 `ccxt`
- `domain/models` 不依赖 repository、UI、交易所客户端或具体持久化实现

这几条不是建议，而是分层约束。若需要跨层协作，必须通过显式接口或中间对象完成。

## 7. 推荐参考方式

推荐按以下方式使用参考仓库：

### A. 看结构，不继承结构

可借鉴：

- 模块如何拆
- 命令入口如何组织
- 对象关系如何命名

不可照搬：

- 完整生命周期
- 框架身份
- 与本项目边界冲突的职责分布

### B. 看接口，不复制语义

可借鉴：

- 策略类 API 形态
- 分析对象命名习惯

不可照搬：

- 交易语义
- 止损止盈逻辑
- 事件流状态机

### C. 看流程，不引入冗余依赖

可借鉴：

- 回测任务流
- 参数实验流

不可照搬：

- 不必要依赖
- 历史兼容层
- 超出 v1 边界的插件或控制组件

## 8. 参考笔记要求

建议维护：

```text
references/REFERENCE_NOTES.md
```

只记录以下内容：

- 哪个参考仓库值得借鉴什么
- 哪个实现思路不适合本项目
- 哪些命名和分层可以吸收
- 固定到哪个 tag 或 commit
- 明确参考范围和排除范围

不记录：

- 大段源码摘抄
- 临时复制的实现草稿

建议记录格式：

```text
仓库名
- 路径：
- 版本：
- 参考范围：
- 排除范围：
```
